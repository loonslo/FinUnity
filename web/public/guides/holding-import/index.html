持仓截图导入：识别以后，逐项核对

截图识别只是准备记录。导入前核对来源、证券、币种、数量、价格与成本，确认写入后再检查账本结果。

上传前

  1. 确认有权处理图片，遮挡姓名、账号、证件号码等与持仓识别无关的信息。
  2. 保留证券名称或代码、币种、数量及必要成本信息，避免裁掉表头或单位。
  3. 阅读数据处理说明：截图会发送到服务器及配置的第三方识别服务，不是完全本机 OCR。
  4. 核对当前识别是否启用、配额与错误提示。不可用时使用界面提供的手工或表格方式，不反复上传敏感图尝试绕过限制。

解析、预览、确认是三个步骤

原图由 FinUnity 在请求内存中处理，不写入它的图片文件或数据库；第三方处理与留存仍适用其政策。识别出的结构化记录会在服务器留档，因此“不保存原图”不等于“不保存任何导入数据”。在预览里逐行编辑和核对，用户确认后才写入持仓。

字段核对方法
证券与来源代码、市场、名称和所属账户是否对应，不把同名产品合并
币种与单位确认 CNY/USD 等；千元、份、股和金额不能混用
数量与价格检查小数、符号、截图列名及价格口径
成本确认原图是单位成本还是总成本，不把市值当作成本
写入动作按界面实际提供的操作和预览检查，不把已存在持仓再次当成新增

虚构的识别错误

假设原图写“数量 12.5，单位成本 USD 80”，预览变成“125，CNY 80”。应先改正数量与币种，再核对成本列的含义；能读到证券名称并不意味着整行准确。这个例子是人为构造的错误，不是模型准确率测量。

部分失败与结果不确定

  • 某张图识别失败：按界面重试该图，复核已成功记录，避免整批重复导入。
  • 保存请求超时或结果未确认：保留原批次，按提示重试；不要建立一个新的相同批次来碰运气。
  • 看到成功提示后：回到账本核对账户、数量、币种和汇总，不能只以网络返回成功证明记录正确。

上游、配额和网络都可能导致失败。截图、表格或手工录入都需要同样的字段核对；本指南不宣称识别完全准确。
