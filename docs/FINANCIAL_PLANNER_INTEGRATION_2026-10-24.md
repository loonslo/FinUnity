# 财务规划原型并入 FinUnity

日期：2026-10-24

## 目标

将 FinUnityPrototype 中的目标测算、方案版本、实际投入跟踪与月度复盘并入 FinUnity Android。FinUnity 是唯一正式产品；原型的 React 页面、FastAPI 本机服务和独立 SQLite 不作为运行时依赖。原型仓库在迁移验收完成前仅作规则和视觉参考。

## 架构

- Android 页面使用 Jetpack Compose，延续 FinUnity 导航和本地 Room 数据库。
- 规划计算放在独立、无副作用的 Kotlin domain engine 中；新规划金额以十进制字符串持久化并以 `BigDecimal` 计算。
- 现有账户、资产、负债、流水和周期规则由 FinUnity 保持为原始数据来源。资产配置目标与人生/家庭财务目标分属不同模型。
- 新增规划档案、财务目标、方案版本和复盘数据。确认方案冻结输入、情景和结果；输入变化使草案失效，历史已确认版本不被覆盖。
- 实际投入通过目标标记关联到 FinUnity 的真实流水。计划行动、预测收支和方案测算不自动改动资产或账本。
- 第一阶段保持离线可用，不接入原型 AI 助手或其本机服务；后续如需 AI/同步，另行定义 FinUnityServer API、授权和数据最小化规则。

## 关键取舍与风险

- FinUnity 现有金额字段以 `Double` 保存；规划输入和新规划结果使用十进制字符串，读取旧数据时通过显式转换并统一货币精度，不能把缺失汇率当成 1。
- 现有 `RecurringRule` 到期后会生成账本流水。规划测算要区分周期假设与已生成的实际流水，避免双计。
- 现金应急预留先于目标资金分配；锁定资产、房产和未知金额不纳入可自由安排现金。
- Room schema 与 JSON 备份都需要向前迁移。旧备份缺少新规划字段时应恢复为空规划，不丢失原账户、资产、流水或历史快照。
- 原型数据库不自动复制进 Android。若确有本地规划资料需要迁入，另做可预览、可取消、可回滚的导入流程。

## 第一阶段验收

- 能从 FinUnity 规划页进入目标规划，页面在浅色/深色模式和手机宽度下可用。
- 能维护目标和月度财务输入，展示应急预留、可安排资金、月度预算、目标缺口及情景结果。
- 能保存并确认方案版本；旧版本保留，源数据变化时不将过期草案误标为当前方案。
- 实际投入只在用户确认后写入既有流水，目标进度不因预测或重复操作虚增。
- 新 Room 迁移、备份导出/恢复兼容旧数据；纯计算覆盖零预算、缺字段、超分配、负债/锁定资金排除、目标已过期等边界。
- 记录实际执行环境、通过项及未验收项后，再更新 FinUnity 根目录 `PROJECT_STATUS.md`。

## 后续阶段

- 端到端迁移原型的批量记录、对账调整、历史复盘和 AI 助手；逐项映射到 FinUnity 已有账本语义，避免重复造账。
- 完成移动端业务与数据迁移验收后，将原型作为已并入的历史参考处理，不继续单独维护第二套产品。

## 实施与验证记录（2026-10-24）

已并入 FinUnity Android 的第一版实现：

- 在 FinUnity「规划」页加入「目标规划」入口，使用暖白橄榄主题、Compose 页面和现有导航；新安装默认浅色橄榄主题，升级时把旧的默认深蓝主题迁为浅色橄榄，用户仍可在设置中更换。
- 新增月度财务资料、家庭目标、方案版本和月度复盘 Room 表；数据库从 v26 迁至 v27。方案草案以输入指纹识别过期，确认版本保留历史。
- 使用 BigDecimal 在本机计算预留、月度预算、优先级投入、目标期限、情景收益/通胀与缺口。现金来自 FinUnity 未锁定现金资产；现金币种缺汇率时阻止确认。
- 实际目标投入需用户确认后，通过既有转账账本记录；目标收款账户限定为基准币种，避免跨币种复盘误加。规划与情景试算本身不生成流水。
- JSON 备份升至 v10，加入新规划资料；旧备份没有这些字段时按空规划恢复，并校验目标流水及方案复盘引用。
- Prototype 原目录、本机数据库及独立仓库未修改或删除，也没有将其中历史数据自动导入 FinUnity；目前仅作为迁移参照。

本次验证环境为 Windows 工作区。2026-10-24 执行 `gradlew.bat :app:assembleDebug` 成功；`:app:testDebugUnitTest` 的 154 项单元测试全部通过，其中新增规划计算测试 4 项；`:app:compileDebugAndroidTestKotlin` 成功编译迁移和备份测试源码，Room KSP 生成 v27 schema。环境未识别 `adb`，因此没有运行设备上的 Room 迁移与备份恢复测试，也未安装应用做页面验收。原型历史资料的导入规则仍未实现。后续需在有 Android SDK/模拟器的环境运行 connected tests，再做页面验收和历史资料迁移决策。
