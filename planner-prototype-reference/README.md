## 启动

本目录是历史参考快照，不再作为独立前端项目维护。公开 monorepo 已移除 `frontend/vite.config.ts`，因此 `npm run dev` 不再使用原来的 `5174` 端口及 `/api` 到本机 `8011` 的 Vite 代理。下面的启动方式属于历史说明，本次没有复验；当前前端请使用仓库根目录的 `web/` 模块。原始独立工作目录保留在 monorepo 外，供历史对照。

需要 Python 3.12（由 uv 管理）、uv、Node.js 22+。

在项目根目录运行：

```powershell
.\start.ps1
# 不自动打开浏览器：.\start.ps1 -NoBrowser
```

访问 http://127.0.0.1:8011 。启动脚本先安装锁定依赖、构建页面，再启动单进程本机服务。Ctrl+C 停止。不要将该原型绑定到公网。

需要在自己的服务器上私下使用时，参照 [服务器运行说明](deploy/README.md)：容器端口仍只绑定服务器的 `127.0.0.1:8011`，通过 SSH 隧道访问。原型没有登录或多用户隔离，不得配置公网反向代理。

默认数据库是 `backend/finunity-prototype.db`，与上游 Aurelio、既有 FinUnity 的数据库独立。历史原型源代码曾推送到单独的 GitHub 仓库；2026-10-24 起本目录源码快照也属于公开 `loonslo/FinUnity` 仓库。旧服务器实例使用自己的空数据库，没有导入本机账目或凭据。首次使用时页面为空，点击“用示例体验”可以填入虚构家庭，检查后保存。

## AI 配置

没有密钥也能完成建档、全部测算、方案确认、执行记录与复盘。启用 AI 时，把 `backend/.env.example` 复制为 `backend/.env`，自行填写 `OPENROUTER_API_KEY` 与支持工具调用的 `OPENROUTER_MODEL`，再重启服务。密钥只由后端读取。调用将向 OpenRouter 和所选模型服务发送当前建档、测算上下文与问题。

每任务最多 4 次模型请求、每次最多 2048 输出 token、单次超时 45 秒、每日最多 10 个任务（UTC 日界线，北京时间 08:00 重置），不自动重试。该限制不等于美元费用上限；请在模型供应商账户设置消费上限。真实供应商费用缺失时显示“待核对”。

## 体验完整闭环

1. 进入财务建档，填入示例或自己的账户、负债、月收支与目标。余额日期是该日的日终记录；预测不代表到账。
2. 为目标分配现有资金，关联服务于目标的定投，保存。分配是用途标记，不能重复占用现金或应急预留。
3. 进入方案测算，比较月投入、期限、额外收支与显式收益/通胀假设，生成待确认方案。查看缺口与假设后确认采用。
4. 在执行与复盘中，从投入计划点击“记录本次投入”即可带入目标、计划与剩余金额，核对账户后保存。分多次投入会自动累计，未足额时显示部分完成；已有目标流水也会自动匹配。
5. 记录普通收支、转账或还款时，明确选择增加或减少，金额只填正数，页面展示账户两端的变化。“再加一条记录”支持多条一次保存，有一条失败则整批不入账。只有“已发生”影响余额；记录日期必须晚于相关账户日终日期。内部转账不算收入，作废保留审计并重新计算投入进度。
6. 生成本月复盘；同一方案当月只保留一份，重复点击更新已有结果。记录变化后会提示更新，旧月份与旧方案复盘折叠为历史。无记录不等于实际为零。依据偏差调整条件，再确认新方案，旧版保留。

每个方案版本生成当月行动。跨月可明确沿用方案生成本月计划；建档条件改变时先重新测算确认。次月 1–10 日可补做上月收官复盘（含上月有行动的历史方案）。本月投入进度不受余额基准日影响。

账户旁的“对账”核对今天的银行或机构余额，生成可作废的独立差额调整，基准日不变，不计入收入、支出或目标投入。建档与记账草稿自动保存在本机浏览器存储；其它操作与切页不清空，离开页面前提醒。

## 开发与验证

以下命令是原型归档时保留的历史说明。由于公开快照不再包含 Vite 配置，本目录的 React 开发服务器不再具有原先的端口与 API 代理设置；本次没有重新运行原型构建或测试。

```powershell
# 后端
cd backend
uv sync --locked --group dev
uv run uvicorn app.prototype:app --host 127.0.0.1 --port 8011 --workers 1
# 另一个终端：前端本机开发
cd frontend
npm ci
npm run dev
```

归档前端此前使用过开发端口 5174，并将 API 代理到本机 8011；对应 Vite 配置已从当前公开快照移除。`npm run build` 从后端 OpenAPI 自动生成类型。

规划后端测试为 `backend/tests/test_financial_planner.py` 与 `backend/tests/test_planner_lifecycle.py`；前端纯函数测试可运行 `npm run test:planner`，真实 React + API 页面复验为 `npm run test:planner:browser`（先启动临时测试服务，见本次验收）。最新界面精简与复盘验收见 [改进记录](docs/UI_REVIEW_2026-10-19.md)；投入录入改进及验收见 [交互改进记录](docs/EXECUTION_INTERACTION_2026-10-19.md)，初版验收见 [docs/VALIDATION.md](docs/VALIDATION.md)，架构、状态与接口见 [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md)。

上游 README 保留在 [docs/UPSTREAM_README.md](docs/UPSTREAM_README.md)。原服务器方案保留在 [docs/finunity-web-server-plan.md](docs/finunity-web-server-plan.md)，其中多人隔离、OIDC、Redis/Celery 与全球市场接入属于后续阶段。

## 当前边界

中文、CNY 与上海时间优先；可保留外币余额并手动填写汇率。行情、基金穿透与旧版页面源代码保留供参考，原型入口没有挂载旧接口或自动补交易。没有自动迁移旧账目、多人登录、自动交易、自动报税或完整会计总账。

AI 任务与结果会保存；刷新页面可以继续查看。应用重启会将未结束任务标为中断，并保留可能发生费用的提示，不自动重放供应商调用。
