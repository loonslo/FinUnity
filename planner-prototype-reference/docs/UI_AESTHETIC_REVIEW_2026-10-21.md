# 界面审美与交互评审

日期：2026-10-21（Asia/Shanghai）。对象：本机规划原型 V2（四页布局、记账抽屉、助手抽屉、手机底部导航）。性质：只读评审，只提方案；评审时没有修改代码，也没有启动应用。

## 评审方式与证据

- **真实界面截图**：[validation-2026-10-21/images](validation-2026-10-21/images) 下 16 张，含暗色、390px 手机、出错、过期草案和跨月状态。下文“截图 NN”均指该目录里的文件编号。
- **源码**：`frontend/src/planner/` 下的 `PlannerApp.tsx`、`Summary.tsx`、`Scenarios.tsx`、`RecordSheet.tsx`、`HouseholdEditor.tsx`、`execution.ts`、`ui.tsx`、`planner.css`。文中行号以 2026-10-21 的工作副本为准，代码变动后会偏移。
- **对照材料**：设计参考 [optimized-prototype](audit-2026-10-19/optimized-prototype/index.html)、上轮评审 [PROTOTYPE_AUDIT_2026-10-19](PROTOTYPE_AUDIT_2026-10-19.md)、整改验收 [AUDIT_IMPLEMENTATION_2026-10-21](AUDIT_IMPLEMENTATION_2026-10-21.md)。上轮 39 项以数据正确性和流程为主，已全部落地；本次侧重视觉层级、信息密度和操作步数。
- **本机字体**：核对了系统字体目录，中文衬线只有华文宋体（STSong）和宋体（SimSun），没有思源宋体。

## 总评

| 方向 | 结论 |
|---|---|
| 是否存在问题 | 有，确定的缺陷 9 处（F1–F9）。最影响观感的两处：顶部“下一步”按钮在它指向的那一页上点了没反应；记账出错时同一句话重复显示 |
| 哪些不合理 | 同一屏主按钮重复；装饰手法叠得太多；说明文字过量；导航名和页面标题对不上（R1–R8） |
| 是否足够现代 | 风格有辨识度，不像模板。但页面没有动效、表单味重，中文标题字体显旧。中等水平（M1–M8） |
| 操作是否简洁 | 记一笔计划内投入只要 2 步，很好；普通记账、确认方案、建档仍然偏重（S1–S5） |

**值得保留**：暖骨色加橄榄绿的克制配色和“浓咖啡”暗色；预算的账本式算式；目标三段进度条和目标旗标；“怎么补上缺口”三张一键带入试算的卡片；记账抽屉底部固定的余额预览；焦点环、跳到主要内容、抽屉焦点约束等无障碍基础。

## 一、确定存在的问题（F）

|---|---|---|---|

## 二、不合理的地方（R）

### R1 主按钮太多，“每页只给一件事”没做到

- [截图 04](validation-2026-10-21/images/04-execution.png)：执行页第一屏同时有 3 个实心主按钮——顶部“记录本次投入”、页头“＋记一笔”、卡片里的“记录本次投入”；手机上再加一个悬浮“记一笔”。
- [截图 01](validation-2026-10-21/images/01-overview.png) 首页、截图 10 空状态都是上下两份一模一样的按钮。
- [截图 05](validation-2026-10-21/images/05-record-sheet.png)：记账抽屉里选中的“今天”胶囊也是实心橄榄绿，和“保存”按钮长得一样。
- 选中状态有两套样式：黑底胶囊（流水筛选、草稿标签）和橄榄底胶囊（试算标签、今天/昨天）；另有一套分段控件样式写了但没有使用。
- 建议：同一屏只留一个实心主按钮；选中状态统一为浅底加描边。

### R2 导航名和页面标题对不上

- 点“执行与复盘”看到的标题是“每月做一点，变化看得见。”；“方案测算”对应“比较不同的安排”；“财务建档”对应“先把现状说清楚”。
- 标题上方的小字一页一种意思：日期、修订号、“试算 → 方案”、“第 3 步”。
- 建议：标题直接用导航名，口号降为副标题；上方小字统一写状态。

### R3 导航结构与使用频率不符

- 侧栏“每月一圈”把“财务建档”也算进每月循环，但建档通常只做一次，日常主要停在执行页。建议按使用频率排：概览 / 本月 / 方案 / 资料；流程感交给“下一步”条表达。
- 执行页以“本月”为中心，流水表却不分月：截图 08 的 11 月页面里列的全是 10 月记录（`PlannerApp.tsx:969` 只按状态筛选）。建议按月分组，或加月份切换。

### R4 首页太长，主次不分

- 1440 宽时整页 2821px（约 3 屏），390 宽时 5026px（约 6 屏），见截图 01、[截图 12](validation-2026-10-21/images/12-mobile-overview.png)。
- “04 这些数字从哪来”是排查用的信息，却默认展开（`Summary.tsx:565`）。
- “本月行动”和执行页的“本月投入计划”是同一组卡片重复出现。
- 建议：首页只放三件事——可自由安排的现金、本月进度、目标缺口。来源说明默认折叠，或改成数字旁的 ⓘ；本月行动压成一行（“还差 ¥3,000 · 1/2 完成 [记录]”）。

### R5 装饰手法叠得太多

- 线有 6 种：发丝线、1.5px 墨线、双下划线、点状引线、虚线分隔、虚线框。
- 斜纹有 5 处，各表示不同意思：应急预留、未来投入、缺口、不易变现、图例。
- 左侧色边卡片有 5 种：下一步、续期、草案、未保存栏、余额预览。
- 另有 01–04 衬线编号和纸面噪点。单看都讲究，放在一屏就成了噪音；暗色下斜纹更扎眼（[截图 11](validation-2026-10-21/images/11-dark.png)）。
- 资金分层条里最重的深色斜纹给了“应急预留”（`planner.css:246`），主数字对应的“可自由安排”反而颜色最浅，轻重正好反了。
- 建议：线型最多留 3 种（发丝线、合计双线、引线）；斜纹只表示“估算 / 预测”一种意思；左侧色边只给需要处理的状态；分区编号只保留在建档这种真有先后顺序的页面；分层条让“可自由安排”最醒目。

### R6 大号衬线数字用得太多

- 投入卡、目标卡、复盘格各有 3 个一样大的数字，主数字反而不突出。
- 建议：衬线大字只给每页 1–2 个核心数字，其余用无衬线等宽数字，并单独突出“还需投入”。

### R7 说明文字太多，用词偏开发视角

- 规划页源码里有 31 处提示文字、10 处标题旁注，几乎每张卡都附一句说明（“不会重复扣减”“基准日不变”“不会替你认定已经交易”）。
- “修订 1 / 账目修订 6 / 测算修订 1 / 日终 / 基准 / 数值质量 / 核销”这类词直接给用户看。
- 这些是逐条修上轮评审问题时“补一句说明”攒出来的。
- 建议：每页只留影响决策的 1–2 句，其余收进 ⓘ 或“了解口径”折叠；修订号改成时间，比如“10 月 19 日保存”。

### R8 卡片和背景几乎同色

- 卡面 `#fffdf9` 对背景 `#faf8f3`，只靠 1px 发丝线分隔（`planner.css:25`），普通显示器上卡片边界发虚。
- 建议：拉开两者的明度差，或给卡片加一层很淡的阴影。

## 三、现代化程度（M）

整体方向（Editoriale：暖骨色、橄榄绿、衬线数字、账本引线）不过时，也没有渐变、玻璃拟态这类模板痕迹。显旧的主要是实现细节：

| 编号 | 显旧的地方 | 建议做法 |
|---|---|---|
| M1 | 中文标题落到了华文宋体。字体列表里排在前面的思源宋体（Noto Serif SC、Source Han Serif SC）本机都没装（`planner.css:23`）。50px 标题笔画发细，像 Word 文档，和窄高的 Instrument Serif 数字也不搭；没装 Office 的电脑会落到宋体，效果更差 | 随项目打包思源宋体的常用字子集；或中文标题改用中粗黑体，衬线只留给数字和拉丁字母 |
| M2 | 页面完全是静的。设计稿有换页时逐层浮现、进度条生长、记账后卡片闪一下；样式已搬进 `planner.css:557-559`，但 React 代码从未挂上 `.play`、`.rv`、`.pulse`。保存后只有底部提示，看不出哪张卡变了 | 接回这三种动效；试算结果变化时数字短暂高亮 |
| M3 | 系统原生的下拉框和日期框太多（建档页 11 个下拉，记一笔目标投入时 7 个），像后台管理表单 | 类型、发生状态、账户改成并排选项按钮或卡片单选；日期用“今天 / 昨天 / 选日期”一行胶囊 |
| M4 | 需要手动点的“刷新”按钮（`PlannerApp.tsx:622`） | 切回窗口时自动刷新；按钮的位置改放常驻“＋记一笔”（见 S5） |
| M5 | 先打勾再点按钮的确认方式（沿用方案、确认方案草案） | 保留“必须明确接受缺口”的口径（上轮 I9），但写进按钮文字，例如“接受 ¥4,000 缺口并采用”，少一个控件 |
| M6 | 手机上的流水是 760px 宽、要左右滑动的表格 | 小屏改成两行一条的卡片列表，作废收进行内菜单 |
| M7 | 口号说“变化看得见”，但全站只有当月数据 | 加一张近 6 个月“计划 vs 实际投入”的小柱图，或目标进度轨迹 |
| M8 | 桌面端没有快捷键 | 例如 `N` 记一笔、`1`–`4` 切换页面 |

## 四、操作是否简洁（S）

主要路径的步数（按代码推算）：

| 任务 | 现在的步骤 | 卡在哪 |
|---|---|---|
| 记一笔计划内投入 | 2 步：记录本次投入 → 保存 | 保持现状 |
| 在电脑上记一笔普通支出 | 先切到执行页 → ＋记一笔 → 填金额 → 保存（有多个现金账户时还要选账户） | 首页、建档、测算页在电脑上没有记账入口；悬浮按钮只在屏宽 ≤1000px 时出现（`planner.css:545`） |
| 新月份沿用方案 | 从首页点顶部按钮跳到执行页 → 打勾 → 再点一次 | 人在执行页时顶部按钮无反应（F1）；打勾可以并进按钮（M5） |
| 生成并确认方案 | 调参数 → 生成草案 → 滚回页面顶部找草案 → 有缺口时打勾 → 确认 | 草案出现在页面最上方，离刚点的按钮很远（`Scenarios.tsx:117`） |
| 把目标延期 12 个月 | 点 12 下“＋” | 一次加一个月的按钮不适合大范围调整 |

### S1 记账抽屉重新排序

- 金额放第一位，用大号输入框并自动聚焦；类型用 4 个并排按钮（收入 / 支出 / 转账 / 还款）；然后是账户和日期胶囊。
- “发生状态”默认“已发生”，收进“更多选项”。
- 现在手机上金额框在第一屏以外（[截图 13](validation-2026-10-21/images/13-mobile-sheet.png)），重排后可以直接看到。
- 类型文字“减少支出”（`execution.ts:4`）在中文里读起来像“少花钱”，改成“支出 −”；“增加收入”同理改成“收入 ＋”。

### S2 多条记录改成列表

- 保留整批保存、任一条失败整批回滚的规则（见[最终方案](final/FINAL_PLAN.md)第四、五节）。
- 把“第 1 条 / 第 2 条”标签页换成抽屉顶部的紧凑列表，并加一个“保存并再记一条”。

### S3 试算对比表减少干扰

- [截图 03](validation-2026-10-21/images/03-scenarios.png) 里“与当前方案相同”出现了 17 次；“试算 A”默认就是当前方案的复制，整列都是这句话。
- 没变化的格子留空，只显示变化；正在编辑的那一列整列高亮。
- 收益率给 0% / 3% / 5% 预设，延期给 +3 / +6 / +12 个月。
- “生成方案草案”改成弹出确认抽屉（差异摘要 + 缺口 + 确认按钮），看差异和确认在一处完成。

### S4 建档页表格化

- 账户、负债、目标改成表格，表头只出现一次，不再每行重复 6 个字段名（`HouseholdEditor.tsx:320`）。
- 金额输入加 ¥ 和千分位：现在的 `1200000` 很难读，样式也和测算页右对齐带 ¥ 的输入不一致。
- 来源、数值质量、单个账户的日终日期收进行展开；4 个“已完整填写”勾选移到保存前的核对步骤。
- 首次建档可以做成 3 步向导：收支 → 账户 → 目标。

### S5 电脑端常驻“＋记一笔”

- 顶栏放一个常驻“＋记一笔”，和手机的悬浮按钮对应；顶部“下一步”条只负责计划内的那一件事。

## 验证边界

- 没有启动应用实际点按。F1 是从代码推断的：跳转到当前同一地址不会触发 hashchange，页面状态不变。
- 字体结论只针对这台 Windows 电脑（装有华文宋体和宋体）；Mac 上会换成系统自带的宋体-简。
- Safari、Firefox、屏幕阅读器和真机都没有看；手机结论来自 390px 视口截图。
- 页面高度取自截图像素尺寸；下拉框、提示文字数量取自源码和截图的静态计数，实际数量随数据变化。
- 本评审只给方案，不代表任何一项已经整改。
