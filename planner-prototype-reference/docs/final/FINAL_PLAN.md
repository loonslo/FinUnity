## 一、定位与范围

基于 Aurelio 的独立工作副本，先验证个人与家庭的财务规划闭环：

**建档 → 确定性测算 → 用户确认方案 → 记录实际执行 → 本月复盘 → 调整并确认新版本。**

用户应能看清可用资金、必须支付的费用、多个目标的资金分配、缺口的调整方法与本月行动。家庭资料由同一位使用者维护。本阶段采用本机单用户服务，后续再决定如何整合既有 FinUnity。

原服务器蓝图保留在 [原始参考方案](../finunity-web-server-plan.md)。它是架构参考；本文件与实际代码、验收记录共同界定当前交付，不将参考文档中的未来能力视为已经实现。

## 三、资金与目标规划规则

1. 金额以 Decimal 计算，通过十进制字符串传输；未知金额不能作为零处理。当前未自动导入旧 Float 数据，也不声称恢复旧数据原始精度。
2. 默认中文、CNY、Asia/Shanghai；保留原币、人工汇率与来源。默认零收益、零通胀；其他数值是明确情景假设，不能理解为收益保证。
3. 净资产与可自由安排的现金分开。首页主金额扣除应急预留与已分给目标的现金；房产、受限资产不进入此口径。
4. 应急预留优先；同一笔资金不能超额分配到多个目标。分配只是资金用途标记，不意味着真实转账。
5. 月收入、总支出、最低还款、独立定投和目标投入共用预算。最低还款已含在总支出时不再重复扣减。
6. 与目标关联的定投先按目标合计，再与该目标月投入取较大值；独立定投另计，避免重复扣减。
7. 目标按用户确认的优先级安排月预算，展示可负担金额与缺口；资料不完整、超额承诺或分配冲突时不能确认可执行方案。
8. 情景可以调整投入、期限、目标与收支等条件；结果由计算工具产生，保留输入时点、假设、缺失项和来源。

## 四、财务事实与实际记录

发生状态与数值质量分开保存：发生状态为预测、待确认、已确认或已作废；数值质量为已核实、估算或未知。只有已确认且日期满足账户日终基准要求的记录影响实际余额。已发生但使用估算值的记录明确标识。

| 记录类型 | 账户与资金变化 |
|---|---|
| 增加收入 | 收款账户增加；金额填写正数 |
| 减少支出 | 付款账户减少；金额填写正数 |
| 内部转账 / 目标投入 | 转出账户减少，转入账户增加；内部转账不算收入 |
| 偿还负债 | 现金账户减少；本金减少负债，利息作为成本；纯利息本金可填零 |
| 对账差额调整 | 核对今天的现金或投资账户余额，独立记录差额与方向；可作废，不计入收支、还款或目标投入 |

- 页面在填写金额后预览账户变化。跨币种转账需要两端真实金额；同币种转入金额可留空沿用转出金额。
- 新增目标资金与移动已分配资金分开；移动已有资金不虚增本月投入。
- 实际记录可以关联核销预测或待确认记录，避免到账后重复统计。
- 最多 50 条草稿同批保存；任意一条校验失败则整批回滚。重复提交以标识识别，不重复造账。
- 作废保留原记录与审计；若后续记录依赖该笔资金，先处理依赖。作废后重算目标投入进度。
- 不根据定投到期、公开分红或行情自动认定用户已经交易。

## 五、计划关联、草稿与简洁交互

- 投入计划显示本月计划、已投入、剩余三项。点击“记录本次投入”带入目标、计划和剩余金额，核对账户后保存。
- 同一目标同月的已确认新增投入自动累计。部分投入显示进行中，足额显示已完成；预测、待确认、作废和移动已有资金不计入完成额。
- 资金行动的完成由事实驱动，点击按钮不能制造资金记录。检查型行动可以单独确认。
- 记账抽屉用草稿标签切换；标签上的移除只处理这一条，最后一条恢复空白草稿。草稿和幂等标识自动保存在本机，刷新后可恢复。
- 点击投入计划只替换未编辑的空白草稿；已输入备注、日期、类型等内容时另增草稿，保护已有输入。
- 来源、数值质量、关联预测与备注收进“更多选项”。必要的增减方向、预测不入账说明和错误提示保留。
- 建档默认昨日的日终余额，未保存修改独立保留，保存或放弃后才清空；保存栏不透明。成功提示在浮层显示，可关闭并自动消退。目标用上下移动排序，优先级自动编号。

## 六、本月复盘与方案版本

1. 当前已确认方案可生成或更新本月复盘；上海时间次月 1–10 日可补做上月收官，包含上月确有行动的历史方案。其它历史月份、未来月份不可重新生成。
2. 同一方案、同一月份只展示一份复盘。重复或并发点击更新同一文档，不追加多份。
3. 旧月份、旧方案的既有复盘保留为历史。历史重复文档保留在数据库，读取时按方案和月份合并显示最新一份，不做物理删除。
4. 复盘只汇总已经确认的记录，展示收入、支出、还款以及目标计划与实际的差额。无记录不代表实际没有收支。
5. 记录变化后提示更新复盘；更新复盘不修改建档或流水。余额继续按基准日重放；本月目标投入进度独立统计本月已发生的新增投入，不因重设基准而丢失。
6. 调整后生成新提案，确认后生效；旧方案保留。每个确认版本生成当月行动。跨月由用户明确沿用方案生成本月计划；建档条件改变时重新测算并确认新版本，不在后台自动重设资金安排。

## 七、架构与落库边界

采用 React + FastAPI + SQLAlchemy + SQLite，Python 3.12。前后端通过 OpenAPI 生成类型。入口只绑定本机，单进程运行。

| 层次 | 职责 |
|---|---|
| 财务事实 | 保存建档、原币、来源、日期和实际记录 |
| 确定性引擎 | 计算余额、预算、资金分配、缺口与情景结果 |
| AI 助手 | 理解、追问、调用计算与解释提案 |
| 用户确认 | 检查资料与日期修订，在事务内使方案生效 |

`planning_state` 保存当前建档及修订；`planning_documents` 保存方案、流水、行动、复盘、AI 任务及审计。确认和批量写入使用事务，校验数据修订和日期；重复确认只生效一次。

业务数据库：项目下 `backend/finunity-prototype.db`。独立于 Aurelio 与既有 FinUnity。本次整理不改动财务事实，数据库和模型凭据留在原位置。

接口明细与恢复行为见 [实施说明](../IMPLEMENTATION.md)。运行与配置见 [项目 README](../../README.md)。

## 八、AI 运行与恢复

- 使用一个规划助手与计算工具；未启用多角色深度规划链。
- 提案绑定固定时点的输入和真实计算结果，不能凭模型文字改写余额或直接确认方案。
- 模型密钥在后端读取。每任务最多 4 次请求，每次最多 2048 输出 token；单请求超时 45 秒，每 UTC 日最多 10 个任务（北京时间 08:00 重置），不自动重试。这些是调用量限制，并非金额费用上限。
- 任务状态、结果和已知用量保存。刷新可继续查看，进程中断任务标为中断，不自动重放可能收费的请求。
- 供应商未报告费用时显示待核对；没有配置模型或模型失败时，手动账目、确定性测算与复盘仍可使用。
- 当前尚未进行真实收费模型验收。
