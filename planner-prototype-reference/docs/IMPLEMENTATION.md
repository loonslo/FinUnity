# 本机个人财务规划原型

实施日期：2026-10-19；评审整改更新：2026-10-21。原型基于 Aurelio 提交 a008d7f，在独立副本开发。原始服务器蓝图保留为 finunity-web-server-plan.md；它描述后续方向，不作为本阶段全部实现的声明。

## 架构与状态

- React 中文页面 → `/api/v1/planner` → 确定性 Decimal 引擎 / 领域服务 → 独立 SQLite。
- 财务建档保存账户日终余额、流动性、原币与来源；月收支用于预算预测。只有已确认流水在账户日终日期之后影响余额。
- 整体财务方案独立于上游定投计划。提案冻结建档、流水、计算结果、情景与修订号。确认由 SQLite `BEGIN IMMEDIATE` 串行化；模型调用不持有写锁。
- 两个新增表：planning_state 保存当前建档和修订号；planning_documents 保存有类型的方案、流水、行动、复盘、AI 任务和追加审计文档。金额在 JSON 中保存精确的十进制字符串。
- 预测和待确认流水不计入余额。实际流水可以关联并核销预测。作废保留原始数据、时间和审计；依赖记录未处理时禁止作废。
- 目标投入是账户间转账，与实际收入分别统计。新增投入与移动已分配资金区分；后者移动用途标记，不虚增目标进度。最低还款中的本金减少负债，利息减少净资产。
- 已关联目标的定投先按目标合计，再与目标月投入取较大值；独立定投另计。目标按用户优先级分配月度预算，不足时保留缺口，并阻止超额承诺生效。
- 应急预留优先保留，不能再次分配目标；房产与受限资产保留在净资产口径，不能自动作为现金。

## AI 与恢复

复用上游 OpenRouter 客户端，新助手只提供 `calculate_plan` 读取工具。最终提案必须对应一次实际工具测算，确认时再次校验财务修订号和日期。模型不能编辑账目、调用 SQL 或执行交易。

每次提问创建持久任务，由单进程本机执行器处理。每次供应商请求前记录 unknown 调用，结束后记录用量；最多 4 次请求，每次最多 2048 输出 token，单请求超时 45 秒，SDK 不重试，每 UTC 日最多 10 个任务，同时只允许一个任务。输入上下文限 60000 字符。

上述限制控制请求量，不承诺美元费用硬上限；用户应在供应商设置消费上限。供应商未报告费用时保存 unknown，不能当作零。应用重启将未结束任务标为 interrupted，不重放。普通账目、测算与复盘不依赖模型。

任务读取接口用于页面刷新后的轮询恢复；本阶段未引入 SSE、Redis、Celery 或分布式任务执行。单进程启动限制是当前实现的边界。

## 接口与使用边界

- `GET /state`，`POST /household`：读取与按修订保存建档。
- `POST /calculate`：无副作用的情景测算；`POST /plans`：冻结并保存待确认方案。
- `POST /plans/{id}/confirm`：原子确认，重复调用返回既有结果；陈旧输入返回 409。列表将过期草案读为 stale；`POST /plans/{id}/discard` 放弃未确认草案。
- `POST /plans/{id}/renew`：按修订明确沿用方案，生成当前月行动；相同方案月份在写事务内去重，建档改变则先重新测算。
- `POST /reconciliations`：核对今天的已知现金或投资原币余额，记录可作废的独立差额调整，不计入收入、支出或投入。
- `POST /occurrences`：有幂等标识的单条实际/预测记录；`POST /occurrences/batch`：同一事务保存多条；`POST /occurrences/{id}/void`：保留痕迹作废。
- `GET /actions`：根据目标与月份累计已确认的新增投入，自动显示部分完成或完成；`POST /actions/{id}/complete` 保留兼容，资金行动只有累计金额达标才能完成，不自动造账。
- `POST /plans/{id}/reviews`：生成或更新当前已确认方案的本月复盘；次月上海时间 1–10 日允许补做上月确有行动的方案（含历史方案）复盘；在写事务内按方案和月份更新已有记录。历史重复文档保留，列表按方案与月份合并展示；其它历史月份和未来月份不能重新生成。记录不完整时不声称完整实际。
- `POST /assistant/tasks` 和任务查询接口：保存提问、冻结输入、调用记录与最终结果。

建档、情景和方案类型由后端 OpenAPI 生成。上游旧页面保留在源码用于参考和回归，正式原型入口不挂载旧 API，不运行打开页面自动补交易的逻辑。未自动读取或迁移上游 Float 财务数据；如后续增加迁移，必须 Decimal(str(value)) 转换并保留来源与原始备份，不能宣称恢复精度。

基础设置为中文/CNY/Asia/Shanghai；原币余额和手动汇率可以录入。尚未接入自动行情、银行、证券交易或自动报税。当前基准按月末投入，默认零收益与零通胀；收益使用名义年率/12，不输出成功概率或风险评级。

每个确认版本生成当月行动。进入下一月份后，由用户明确沿用方案生成本月计划，或重新测算确认新方案，不做后台自动规划。余额按日终基准重放，本月进度独立统计本月已发生的新增目标投入。用户主动采用新版本后，旧版未完成行动标为 superseded，旧版方案与已完成记录保留。

## 数据与兼容

默认数据库 backend/finunity-prototype.db，导入任何真实财务数据前自行保留备份。启动入口忽略继承的其他项目 DATABASE_URL；只有明确设置 FINUNITY_DATABASE_URL 才可改变原型数据库。未复制任何 `.env`、数据库或凭据。2026-10-21 源代码推送至私有 GitHub 仓库；服务器使用独立的空 SQLite 数据库，部署记录见 [部署验收](DEPLOYMENT_2026-10-21.md)。

Alembic 新增一个向前迁移，只创建原型表，不修改上游财务表。上游数据库迁移前备份机制继续保留。原型没有多人登录，不应绑定公网或用作共享财务服务。

## 评审整改与验证

建档修订 `household_revision` 从已有审计推导，与普通流水修订区分；旧方案缺字段时回溯原建档修订，无需结构迁移。浏览器草稿独立保留其原始建档，远端建档冲突时不覆盖；写操作继续以服务端乐观修订校验。

视觉基准为 `docs/audit-2026-10-19/optimized-prototype`。产品决策、组件边界、问题逐项对照、真实页面截图及验证命令见 [2026-10-21 整改验收](AUDIT_IMPLEMENTATION_2026-10-21.md)。

## 同日界面审美整改

后续用户授权执行 [界面评审](UI_AESTHETIC_REVIEW_2026-10-21.md)，现行界面为“概览 / 本月 / 方案 / 资料”。沿用现有组件和接口，初次建档分三步，记账金额优先，方案在抽屉中查看差异并明确接受缺口，窗口重新获得焦点时刷新且保护草稿。桌面常驻记录入口；手机提供主题选择、流水卡片和固定预览保存区。

`reviewHistory.ts` 从既有复盘中选择同月最近修订，只展示单目标的十进制字符串结果。同月不同版本不相加，无已记录新增投入、缺汇率或币种不同则不展示实际条。图表表示复盘快照而非实时账簿，保留截至日期；旧快照不会因后续作废而被静默重算。未新增数据库结构或改变后端财务规则。逐项对照与最新截图见 [界面整改验收](UI_AESTHETIC_IMPLEMENTATION_2026-10-21.md)。
