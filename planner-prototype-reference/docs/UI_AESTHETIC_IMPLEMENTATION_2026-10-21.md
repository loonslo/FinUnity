# 界面审美与交互整改验收

日期：2026-10-21（Asia/Shanghai）。依据：[界面审美与交互评审](UI_AESTHETIC_REVIEW_2026-10-21.md)。用户已明确要求执行调整；评审文档中“只读、未改代码”描述的是评审当时的状态，本次没有将它当作禁止实施的指令。

## 设计与状态边界

保留优化稿的暖骨色、橄榄绿、浓咖啡暗色、预算账本、目标三段进度与调整建议。中文标题使用系统黑体，衬线保留给现金与净资产两个核心数字。导航按使用频率排列为“概览 / 本月 / 方案 / 资料”，保留原有 hash 地址，浏览器历史与收藏仍可使用。

React 继续负责交互与展示，后端 Decimal 引擎和写事务负责财务事实。没有数据库迁移，没有新增后端接口，没有修改跨月、复盘窗口、对账或投入计算规则。所有金额仍以十进制字符串提交；千分位仅在资料输入失焦时显示，趋势条只将原有金额转为图形高度，不累计金额、不生成缺失实际值。

建档草稿、记账草稿、试算条件分别保留。窗口重新获得焦点时刷新服务端资料，写入进行中或抽屉打开时不自动刷新；草稿仍使用原有合并与冲突保护。原子批量写入、幂等键、失败回滚沿用原有 API。“保存并再记一条”只在整批提交成功后清空该批并生成新幂等键；失败继续保留原批次。

| R2 | 四个页面标题与导航一致；状态眉题统一表达当前资料、方案或本月状态，原口号作为副标题 |

| R7 | 删除下一步的重复细则，账户的来源、币种、日终和质量收进明细；完整性核对移至保存步骤；保留缺口、未知金额、模型隐私与计费说明 |
| R8 | 保留纸面背景，通过卡片浅阴影、清楚的边界与表面层次区分内容，兼容既有暗色令牌 |

## 现代交互 M1–M8 与简化 S1–S5

| 编号 | 落地方式 |
|---|---|
| M1 | 中文标题使用系统黑体；不增加大体积网络字体 |
| M2 | 页面分区入场与进度生长接入实际组件；核心金额变化短暂变色，投入条目更新后短暂提示；尊重 prefers-reduced-motion |
| M3 | 四种记账类型、三种状态改为选项按钮；账户不超过 4 个时使用可选卡片，更多时使用下拉框；今天/昨天/日期同一行 |
| M4 | 回到窗口自动刷新并保护草稿；顶栏常驻记一笔，替换手动刷新按钮 |
| M5 | 方案确认抽屉集中展示前后月投入、到期日、缺口与假设；有缺口时按钮明确为“接受列示缺口并采用方案”，只有点击后发送 accept_shortfalls；续期也使用明确接受按钮 |
| M6 | 手机流水变成卡片，操作收进每行菜单；无整页横向滚动 |
| M7 | 近六个月按单目标展示已保存复盘的计划和已记录实际；月份缺失、不同币种、缺少汇率或无新增投入记录时不画实际条；同月多版本取最近修订快照，不相加；标明快照截至日 |
| M8 | N 打开记账，1–4 按导航顺序切页；输入控件、抽屉、修饰键和忙碌期间不拦截 |
| S1 | 金额置顶并自动聚焦；状态默认已发生，其他状态收进更多选项；名称改为收入＋/支出−/转账/还款 |
| S2 | 多条草稿显示类型、金额、账户摘要，可切换与移除；新增“保存并再记一条”，维持整批事务边界 |
| S3 | 相同的对比格不重复“与当前方案相同”；所选试算列强调；收益 0/3/5% 和延期 0/3/6/12 月可快捷设置，延期也可直接输入；生成后直接进入确认抽屉 |
| S4 | 初次建档拆为收支、账户与负债、目标与核对三步，未保存可任意返回；已有资料保留完整编辑器；桌面账户、负债、目标使用共享表头，手机恢复字段标签；数字失焦后显示千分位；完整性在保存前核对 |
| S5 | 桌面常驻记录入口；本月页不再重复页头记账按钮；下一步只负责当前阶段的引导 |
