## 本次确认的产品口径

1. **跨月续期**：使用中方案跨月后，用户点击“沿用方案，生成本月计划”，检查条件与缺口后生成行动。每月投入沿用该方案冻结的金额。建档发生变化则先重新测算确认。续期不移动资金、不创建实际流水、不增加账目修订；写事务内去重，重复或并发点击不重复生成行动。
2. **上月收官**：次月上海时间 1–10 日（包含第 10 日）可补做上月复盘；第 11 日起拒绝。历史方案在上月确有行动时也可收官；本月才创建的方案不能补做上月复盘。其它历史月份、未来月份不可新生成。
3. **进度与余额分开**：余额仍从各账户日终基准重放；行动与复盘的本月投入统计所有本月已发生的新增目标转账，不再按建档基准日排除。重设基准不会抹掉本月投入，也不会将已包含在新余额中的流水再记一次。
4. **对账**：现金或投资账户填入今天核对的原币余额，生成独立 `adjustment` 记录，保存差额与增减方向，允许作废。不算收入、支出、还款或目标投入；保持日终基准不变。未知账户余额不能对账；导致既有目标资金冲突的调整拒绝并回滚。无差额核对可保留零差额审计。

## 架构与状态边界

- `PlannerApp.tsx`：加载已保存快照、导航、全局写操作与抽屉编排。
- `drafts.ts`：建档草稿与其原始版本、批次草稿与幂等标识分别保存到本机浏览器存储。普通刷新、试算、记账、作废和切页保留草稿。服务端建档在其它页面改变时保留草稿并阻止覆盖；可核对后放弃草稿读取最新资料。存储不可用时明确提示仅在当前页面保留。
- `HouseholdEditor.tsx`：日终默认昨天、账户与目标、按顺序编号的优先级、分配矩阵、定投与外币来源。JSON 导入先调用无副作用的服务端校验。
- `Scenarios.tsx` / `scenario.ts`：A/B/C 条件与逐目标对比，比例以 % 输入、十进制字符串发送，定投下限和边界错误就地显示；方案确认同草案 ID 绑定。
- `RecordSheet.tsx`：多草稿切换、校验与失败行定位、固定底部余额预览。成功保存才清空，失败保留同一批次标识。
- `Summary.tsx`：资金分层、预算账本、行动与目标、余额来源和复盘；未记录与零分开显示。
- `service.py`：修订校验、串行写事务、续期、对账、草案状态和复盘窗口。
- `engine.py`：Decimal 计算及补缺口选项；“每月需要”向上取整到分。延期与下调是全部目标的试算条件，入口明确提示影响范围；选择后仍需检查对比结果。

`household_revision` 由已有建档审计推导；旧方案缺少该字段时按原修订回溯。新增记录沿用 JSON 文档表，不需要数据库结构迁移。余额基准、实际流水、方案与草稿继续分别管理。

## 验证结果

- 完整后端：**1814 项通过**，其中规划领域 **71 项**（原 54 + 新增生命周期 17）。首次全量因默认 pytest 临时目录权限出现 39 项准备错误；换用项目内全新独立 `--basetemp` 后全量通过，未修改系统目录权限。

- 真实页面：**43 项浏览器检查通过**，使用项目现有无头 Edge / CDP 方式，真实 React 与真实后端，只有日期和数据库隔离。清单：[browser-checks.json](validation-2026-10-21/browser-checks.json)。
- 构建、OpenAPI 类型生成、规划代码与相关前端测试 ESLint、后端 Ruff 均通过。
- 原隔离库脚本保留作历史证据；可执行复验仍只使用临时 SQLite。A 的同日拒绝是保留的安全规则，前端通过默认昨天消除新用户死锁；C 跨月读取不会自动产生行动，必须走新增显式续期接口。

没有进行真实收费模型调用、真实银行对账、生产迁移、Safari/Firefox、屏幕阅读器或真机触屏验收。这里的日期模拟属于测试进程，不是产品里的虚构状态开关。

## 复验

在 `backend` 运行 `uv run --no-sync pytest tests/test_financial_planner.py tests/test_planner_lifecycle.py -q`；全量在 Windows 可使用全新、未存在的 `--basetemp` 路径避开历史临时目录权限。

页面复验先在 `backend` 运行 `uv run --no-sync python tests/planner_ui_server.py`，再在 `frontend` 运行 `npm run build` 和 `npm run test:planner:browser`。测试服务器强制新建临时 SQLite、禁用 dotenv 与模型密钥；测试用 clock/reset 路由只存在于此独立进程。结束后停止测试进程。

日常使用仍从项目根目录运行 `start.ps1`，加载新前后端；本次未自动启动或修改日常数据库。
